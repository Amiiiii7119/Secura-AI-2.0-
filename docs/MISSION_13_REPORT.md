## 2. Issues Confirmed in Previous Implementation & Root Causes

### 2.1 Feature Cache Lineage (Defect B-1)
- **Previous Claim:** `data/ai_detection/features/cached_features.npz` was assumed to represent OpenAI CLIP ViT-L/14 representations.
- **Audit Finding:** The features were actually generated by `extract_deterministic_features` in `extract_ai_features.py` using a procedural surrogate (2D FFT spectrum + RGB histograms + Laplacian gradients).
- **Remediation:** Generated `data/ai_detection/features/cache_manifest.json` marking the cache status as `UNVERIFIED_PROCEDURAL_SURROGATE`. Prohibited claiming research parity with CLIP ViT-L/14 until genuine transformer weights are loaded.

### 2.2 Original-Head ROC-AUC 0.0000 Root Cause (Defect B-2)
- **Previous Claim:** UniversalFakeDetect probe head (`fc_weights.pth`) yielded `ROC-AUC: 0.0000` on the 14-image held-out test split.
- **Mathematical Diagnostic:** UniversalFakeDetect probe weights ($w_{\text{orig}}$) were trained on real CLIP embeddings where synthetic images correlate positively with $w_{\text{orig}}$. When projected onto surrogate spectral features, high-frequency camera noise produced higher dot products ($z \approx -0.68$) than smooth diffusion images ($z \approx -0.80$).
- **Proof:** In Wilcoxon-Mann-Whitney rank concordance, every positive sample had a lower score than every negative sample ($-0.80 < -0.68$). Concordant pairs were 0 out of 40, yielding $\text{ROC-AUC} = \mathbf{0.0000}$.
- **Resolution:** Deterministic test cases added in `test_model_registry.py` mathematically validating the rank concordance calculation and documenting the feature distribution mismatch.

### 2.3 Authentication Deficit (Defect D-1)
- **Previous State:** Zero authentication; endpoints were unauthenticated.
- **Remediation:** Added `backend/app/core/auth.py` and `backend/app/api/auth_routes.py` with PBKDF2-HMAC-SHA256 password hashing, 256-bit session tokens, brute-force rate limiting (HTTP 429), and session revocation.

### 2.4 Model Registry Lifecycle (Defect C-1)
- **Previous State:** Informal status strings.
- **Remediation:** Formalized finite state machine (`READY`, `LOADING`, `UNAVAILABLE`, `FAILED`, `INCOMPATIBLE`) and created `GET /api/v1/models/status`.

- **Algorithm:** PBKDF2-HMAC-SHA256 (100,000 iterations, 16-byte random salt).
- **Session Tokens:** 64-character hexadecimal tokens generated with `secrets.token_hex(32)`.
- **Cookie Policy:** `HttpOnly`, `SameSite=Lax`, configurable `Secure` flag.
- **Rate Limiting:** Enforces 5 failed attempts per 60-second sliding window per IP address; triggers HTTP 429 upon violation.
- **Default Local Workstation Account:**
  - Username: `admin`

  - Role: `Lead Forensic Examiner`
- **Limitations:** Designed for single-workstation local forensic operations. Multi-tenant enterprise deployment requires external database persistence.
